# Diff Plus: design notes

A folder tree overlaid into BB's own Diff tab. BB has no slot beside the tab, so everything here finds the tab by its markup (bb-app 0.47/0.48, undocumented, can change).

## Data

- Files come from the Git plugin's `files` read (`bb--git`), called from `server.ts` (zod is bundled, not shared, so the page does not take it). Viewed marks come from its `viewed` RPC.
- The tab's "Filter files" choices live in a module-level Map inside bb--git, out of reach, so `readFilters` (`src/diff-tab.ts`) takes the toolbar's `filters` prop from its React fiber, re-read when any `aria-checked` on the page changes.
- `src/match.ts` repeats bb--git's path-search rules (picomatch, `dot`/`nocase`, base name without a "/", prefix fallback, "!" parts) to tint rows the search shows. Keep it in step if BB changes them.
- Clicks go through BB's search box with glob characters escaped (`src/folders.ts`). Typing there is heard by a capture `input` listener on each tab's toolbar, never on the document: a document-wide one runs on every composer keystroke and the Performance plugin blames the first script of a frame for BB's own forced layout.

## Tabs, panes, tree column

- `findDiffTabs` finds each tab; `watchDiffTabs` watches the right panels (`#thread-detail-secondary-panel`, the split panes' `#thread-detail-secondary-panel-<pane id>`, the phone shelf) and re-finds every second. The interval and the visibility listener do nothing while the page is out of sight and rescan once when it is back.
- In a split workspace each pane has its own right panel, which moves to the focused pane, in the same layout box as every pane's timeline. `paneThread` reads the thread from the timeline of the pane named in the panel's id, not the first row in the box. A tab in a pane's panel never falls back to the focused thread (`inPanePanel`): it waits for its pane's timeline.
- `TreeColumn` renders the tree element and the "Changes" row in every state (loading, error, empty, ready); only what is under it changes, with a spinner while files load or the open folders are not chosen yet.
- On/off and width live in localStorage, not settings, because a setting write remounts the right panel. Open at first defaults to All.
- Synced view orders the tree like BB's cards (tracked files by path, then untracked; `buildTree(files, compact, synced)` puts a folder where its first file is). `watchVisibleCards` (`src/diff-tab.ts`) and `useInView` (`src/Tree.tsx`) mark rows with `data-in-view` straight on the DOM, so scrolling never re-renders the tree. An IntersectionObserver is rooted at the list scroller; a MutationObserver on the cards' box hands it new cards; one-level watches re-attach when BB replaces the list box, its children or the scroller. An open folder's row between marked rows is marked too; bars slide with Web Animations on `::before`. When marked rows leave the tree's scroll view it scrolls just enough to show them, except within 1.5s of the reader's own input. While off it attaches nothing.
- Pinned rows: "Changes" and each open folder's row (class `diff-plus-` + the pin word, `top` by depth, opaque, inside its wrapper, which ends it) are pinned by the browser (native CSS pinning) with no script on the scroll path (a scripted version lagged the compositor). `useStuckRows` only places the soft edge and caps the levels (`room`, 40% of the view): `.diff-plus-shade` is a zero-height element at the tree's top that never un-sticks, moved down by `--diff-plus-covered` (an edge cast by the pinned rows themselves left stale paint in Brave).
- Keyboard: `useTreeKeys` (`src/Tree.tsx`) gives the tree roving focus (one tab stop) and VS Code's keys: Up/Down, Home/End, Right opens or steps in, Left closes or goes to the parent; Enter/Space are the buttons' own click.

## Recent commits (`src/Picker.tsx`, `server.ts`)

- BB's scope picker lists only commits since the merge base and drops a picked commit outside them, and the SDK cannot open another plugin's tab with a target. So the plugin orders BB's menu items with CSS `order`, portals its own commit rows into the menu, and on a click moves the merge base back N commits (`show_recent`), waits for BB to list the commit and clicks BB's own item.
- The merge base is BB metadata per checkout, not git: every thread on the checkout, the Diff tab's All/Committed views and `bb git status` see it (the composer's context row shows only uncommitted changes). Every exit puts it back: an abandoned pick, any other scope, the plugin's dispose and its startup (`restoreAll` over the `recent:<env>` records). Calls are serialised per environment; each move and restore is logged at info with its reason.
- The page asks `restore_base` once per environment (and Recent commits setting) per page load, then only while its own pick has the base moved (`baseMoved`).

## Icons

- `src/icons-css.ts` (generated by `scripts/icons.mjs` from the installed vscode-icons extension; do not edit, don't round path numbers) holds the stylesheet as a string, ~177KB. `src/icon-sheet.ts` imports it dynamically and adopts it the first time a Diff tab is on the page, so pages that never open one never parse it. `src/icon-map.ts` maps names, extensions and folders to icons; `src/file-icons.ts` looks a path up VS Code's way.
- Data URIs are decoded before the SVG is read, so the script writes two SVG attribute names with one letter percent-encoded (`fil%74er`, `transfor%6d`): the plugin build turns any bare utility word in the folder into a page-wide rule.

## Gotchas

- No Tailwind utility words anywhere in the folder (code, comments, READMEs, strings): `bb plugin build` scopes each as a page-wide `:where([data-bb-plugin="diff-plus"], …) .word` rule. The words that bit here are CSS property and value names (the list is in the build's own output: `grep -o ':where(\[data-bb-plugin=diff-plus.*' dist/app.css`). Prose says "search"/"pinned"/"in progress"; code builds a word from two strings where it must (`pnpm -F`, `["bloc" + "k"]`, `document.visibilityState.startsWith("hid")`). Standalone `.filter(` calls are fine. Check `dist/app.css` for `:where([data-bb-plugin=` after a build (expect 0).
- Don't add buttons over BB's diffs: BB already has "Add to chat" on selected lines. Never pad the top of BB's list scroller (a pinned card header leaves a strip).
- Headless checks: Diff panel open via the right panel's "Show diff panel" button; use `page.mouse.click` for the scope picker. Picking a recent commit moves the checkout's merge base; leave the tab on All changes.
