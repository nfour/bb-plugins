# Lexicon: design notes

Colours a project's key terms in replies and prompts with the CSS Custom Highlight API, so nothing is added to BB's DOM, and writes nothing to the workspace. The user-facing description is in `README.md`; this file is for whoever changes the code.

## Where terms come from

- The project's own terms: a per-project `Store` in plugin kv (`store:<projectId>`, migrated from the older `terms:<projectId>` text), edited from the Lexicon page, by agents, or with `bb lexicon import|export|lint` (`src/cli.ts`).
- Built-in outcomes and actions (`src/defaults.ts`, `DEFAULT_REVISION`), switchable per id for every project (`set_default` RPC, kv `defaults-off`).
- Names learned in the backend from tracked source (`src/scan.ts`, `src/symbols.ts`): package names and exported compound identifiers by a declaration regex, since BB has no language server and the TypeScript compiler is too big for the bundle. Single words are left out. `git ls-files`, at most 1200 files of 200KB, trusted for 60s, stale served while the next scan runs; each scan also runs `sweep` on the store.
- `assemble` (`src/lexicon.ts`): project terms first, then built-ins (those switched off marked `disabled`), then learned names; where two claim a wording the earlier keeps it (`ownership`, pure: an entry that keeps all its wordings is shared, one that loses some is a copy, and it returns the issues too). The server assembles once per environment and revision, so every pane shares the array.

## Pure core (shared by server, page and tests)

- `src/lexicon.ts`: kinds (`name feature option code action outcome topic`), parse and lint, hue (own, else a same-kind parent's, else tone or kind), `compile` to a `Matcher` (single tokens in a Map, other phrases in one regex), `findTerms` (whole words, longest overlap wins, `-`/`_` and `.ext` join words), `highlightName`/`highlightRule` (one rule per look, `light-dark()` colours, no style draws a line because links do), `houseForm` (Title Case for name, feature, option, topic; identifiers, actions and outcomes as written), `KIND_KEYS` (the setting that switches each kind), `hash`.
- `src/store.ts`: `applyOp` checks an agent's add, alias, rename, retire strictly (one owner per wording, a note of 8 to 160 characters, no plain single words, a parent must exist, user-pinned terms untouchable except for aliases, disabled terms untouchable, at most `MAX_OPS_PER_THREAD` 8 per thread, `MAX_AUTO` 300) and applies it as an `auto` term, or queues it in `pending` when `proposals` is on. A rename keeps the old wording in `retired`, painted as stale. `sweep` flags terms whose identifiers left the source or that went unseen for 30 days and retires them 14 days later. Every change is logged (`MAX_LOG` 40) and `undo` reverses the newest. The user's own `userAdd`, `userAlias` and `userEdit` (pin, keep, remove, approve, reject, disable, enable) go through the same log. `suggest` and `briefing` serve the `~` picker, `digest` the agents' session instructions.
- `src/spans.ts`: the DOM-free half of painting (`joinChunks`, `locate`, `outermost`), tested on plain objects.
- `src/explain.ts`: what the card for a clicked word says (pure, tested); `src/mine.ts`: counts recurring names for the `mine` tool; `src/export.ts`: json, md, yaml, txt.

## Page

- `src/paint.ts` is the content script. Each pane has its own lexicon: a row's thread is the prefix of its `data-timeline-row-id`, one matcher per thread (a thread with none is left plain), and the threads on the page are reported to `src/Loader.tsx`, which resolves each thread's environment and reads the `lexicon` RPC with its revision (`unchanged` when nothing moved). It is not polled: the backend publishes `bb.realtime.publish("changed", {projectId})` (`src/signal.ts`) when a store changes (any edit, agent tool, undo, sweep), when a rescan finds other names, and `projectId: null` when a built-in is switched; the Loader's `useRealtime` hands it to each pane (`panes`), which reads again if the signal concerns its project (a signal during a read asks for one more read after it). A signal is ephemeral, so a reconnect (`useRealtimeConnectionState`) reads every pane once. A 60s read remains as a safety net and is what starts the backend's next source rescan (the scan runs on a read, at most every 60s). The Loader keeps the last entries per environment (12), not the matcher, so changing a kind needs no read; it builds the matcher from the kinds switched on.
- Only mounted rows of `[data-timeline-items]` are painted (ids with `:assistant:`, and `:user` unless `paintPrompts` is off), one MutationObserver per timeline. A change is traced to its paragraph (the nearest of `BREAKS`) and only that paragraph is repainted, at most every 100ms: an added paragraph is its own span, changes inside code fences and controls are ignored, a row that mounts is painted whole. Each held range remembers its paragraph (`Held.owner`), so a repaint removes what lay inside it and `sweep` drops ranges of paragraphs BB removed. Measured headless on a 200-paragraph reply: 20 streamed updates cost 5.8ms in all against 81.8ms when the change lands on the row itself (the old whole-row repaint).
- Standing timers (all pause while the tab is in the background and catch up once on `visibilitychange`): the 400ms scan for timelines that came or went (`arm` in `Engine`), the Loader's 60s safety read. `src/tab.ts` (`tabAway`) reads the state from two strings because the bare property name is a utility class to the build. The 100ms repaint throttle is a one-shot timeout, not a timer.
- A click on a painted word opens a card (`src/popover.ts`, `explain` in `src/explain.ts`: the canonical term, its kind and whose it is, the meaning, other wordings, a stale flag). One `click` listener on the document that leaves at once for a click outside a timeline row, for a link or control, a modified click or a selection being made; otherwise it finds the held range whose rectangle holds the point (`Held.hit` keeps the hit). Text only, no markup. The card listens for a click away, Escape, a scroll and a new window size only while it is open.
- `localStorage["lexicon:debug"]` turns on `window.__lexiconStats` (paints, ms, slowest, rows, terms, roots).

## Backend

- `server.ts`: settings, kv stores serialised per project (`mutate`), RPCs (`set_setting`, `lexicon`, `review`, `overview`, `set_default`, `add_term`, `add_alias`, `context`, `edit`), the `lexicon` and `mine` agent tools (the protocol is the lexicon tool's `instructions`; the tool text is data, never instructions), `bb.agents.configure` (a digest of the project's terms, quoted and escaped as data, at most 4096 characters), and the `~` mention provider (`bb.ui.registerMentionProvider`; the item id is `<projectId>.<termId>` because `resolve` gets only the id; the pill carries `briefing`).
- Settings: `enabled`, `symbols`, `agents`, `proposals`, `paintPrompts` and one `kind…` switch per kind. A new one goes in `SETTING_KEYS` and `settings.define` in `server.ts`, `useOptions` in `src/options.ts`, and the menu or page where it is shown. RPC input must omit undefined keys. The logger takes one string.
- Plugin kv has `get/set/delete/list`; `bb.sdk.threads.output` returns `{output: string | null}`.

## Pages and menus

- `src/Settings.tsx` is the Lexicon page, shown as the settings section and as a nav panel (`navPanel`, path `terms`, which scrolls itself because BB gives a nav panel no scroller). Top: "Plugin global settings", a collapsible two-column box of switches with descriptions and a "Colour these kinds" row of chips. Below: a sheet with a row for the global rules (built-ins, read-only except Enable/Disable) and one per project, with counts from `overview` (read once and after an edit, never polled). Rows open independently (the current project's starts open) into a 400px list grouped by kind (every kind listed, empty or not, each collapsible, a pinned header with a count chip and "+ Add term"). A term is two lines (name, aliases, actions; meaning under); stale first, then agent, then yours, disabled last and dimmed; waiting proposals on top with Approve/Reject; Undo last change. A project's terms are read with `review` only while its row is open; rows use `content-visibility: auto`.
- Disable keeps the entry and its wordings owned, but `compile`, `suggest`, `digest` and `sweep` skip it and agents may not change it.
- "Add to lexicon": a `messageAction` (so also in the assistant text-selection menu; `ctx.selectedText`) opens `src/AddDialog.tsx`, an overlay driven by `src/addState.ts`: a new term (kind guessed, meaning optional) or another wording of an existing term (`add_term`, `add_alias`, project found through `context`). The user's adds are pinned.
- `src/ThreadMenu.ts`: a "Lexicon" thread action whose `choices` submenu has the switches and a link to the settings page (like Chat Dock's). The settings page is the only place for the kind switches.
- BB icon names are its own set; an unknown name renders a bolt. The `~` picker uses `DiffModified`.

## Gotchas

- `bb plugin build` turns any Tailwind utility word standing alone anywhere in the folder (code, comments, tests, README, examples and this file: the common CSS keyword names, `position` values and display values, text-decoration and text-transform words) into a page-wide `:where([data-bb-plugin="lexicon"]…) .word` rule. After every build `grep -c ":where(\[data-bb-plugin=" dist/app.css` must be 0; to find the word, list the rules with `grep -o ":where(\[data-bb-plugin=lexicon\][^{]*" dist/app.css`. Split or reword it: `TABLE = "ta" + "ble"` in `src/Settings.tsx`, `GLOW` in `src/lexicon.ts`, `tabAway` in `src/tab.ts`, tests use "frozen" where a feature needs a name. Property values in `src/styles.css` (a `position` value) are fine. No Tailwind classes; the page's own classes are `lexicon-*` in `src/styles.css`.
- No backticks inside the `PROTOCOL` template string in `server.ts`.
- Underline styles are prohibited (links use them); weight is a thin glow, topics a halo.
- Never write the lexicon to the workspace. Users who want a copy ask an agent for `bb lexicon export --format md|json|yaml|txt`.
- A headless browser draws on the CPU, so its timings are far worse than a real screen's.
